Life Insurance Experience Bench

L2 · measurementmeasured Python2026-10MIT

Before this existed, “AI can do experience analysis” was a vibe. Afterwards there is a number with a denominator, a scorer that counts inventions, and an exam anyone can re-run. It also turns a hiring conversation into evidence.

What it is

Forty-seven sealed A/E scenarios built on 250 000-policy portfolios, scored strictly on a held-out split. Two Qwen 27B models crossed with two harnesses, with the harness snapshots and prompt hashes frozen in the repo, the corpora published as CSV, and the benchmark's own failures documented rather than patched. Full write-up →

Design learnings

  • Freeze the instrument before you quote it — a number without bytes behind it is an anecdote.
  • Two failure modes need two metrics: a miss and an invention are different diseases.
  • A “sandbox” that only advises is not a sandbox; tool calls still need a real jail.
  • Report the run where your own tuning backfired. It became the most useful section.

Control it provides

  • Sealed truth per scenario — no answer-key leakage into prompts.
  • Per-pass manifests make every published figure re-derivable.
  • False-alarm accounting is the two-sided error analysis accuracy scores usually omit.
  • Optimism gap reported: tuning scores, held-out scores, and the distance between them.

Synthetic Life Insurance Data Generator

L1 · dataverified Python2026-08MIT

Nobody can publish real experience data, so without a generator no measurement study can exist at all. This one is also the reason the benchmark has an answer key it can prove.

What it is

Deterministic pure-Python generation of Australian Death, CI, TPD and IP experience — 250 000 policies from a seed, A/E ≈ 1.0 by construction, with anomalies (trend drift, one-off shock, volatility, IP recovery) planted as controls. CLI, Python API and a Streamlit front end; bit-identical on seed 42.

Design learnings

  • Plant controls on the actuals only — leave expected values on the pricing basis, so a deviation is signal.
  • Determinism is a dependency, not a nicety: downstream tests are meaningless without it.
  • The generator's own verification report ships with it, or nobody can trust what it produced.
  • Every assumption cites a published basis rather than my judgement.

Control it provides

  • No personal data by construction — privacy is not a policy here, it's a property.
  • Seed + version pins a dataset exactly, so a claim can be replayed years later.
  • Planted controls give a known correct answer to any downstream tool.

Multi-Agents Underwriter

L4 · governancevariance measured Python2026-08MIT

It shows what an auditable LLM decision path looks like end to end — and, once I ran repeated-invocation testing on it, it stopped being a demo and became evidence about how model output varies.

What it is

Medical, Financial and Compliance agents in structured debate above a deterministic rule engine (declarative JSON rules per product), with escalation, evidence handling through chat, JSONL decision logging and a Streamlit surface — built to run on a local LLM with no cloud dependency. Variance study →

Design learnings

  • Rules first, model second, human last — that ordering is what makes residual variance attributable.
  • The combine rule is a control surface: architecture moved spread from ~20 % to 0 %.
  • Fallback behaviour is part of the decision distribution, not a footnote.
  • Concurrency is a test variable — parallel calls produced a degenerate failure mode.
  • With no ground truth, measure consistency; do not pretend to measure accuracy.

Control it provides

  • Every decision logged as JSONL — a run can be reconstructed and challenged.
  • Rules as versioned JSON gives underwriting change control, not prompt drift.
  • Escalation thresholds and conservatism as explicit parameters somebody must set.
  • Repeated-run re-testing as the early-warning control for silent model drift.

Experience Analysis Dashboard

L3 · judgementdemonstrated HTML2026-05MIT

This is the actual actuarial method in the open — so someone can argue with the assumptions instead of the summary. It is also the pattern a team can copy: analysis that carries its own provenance.

What it is

An Australian TPD incidence study: credibility weighting, A/E, Mann-Kendall trend tests, GLM, random forest / GBM and MOB trees over roughly 200 000 exposure records, 7 occupation classes and 7 diagnosis groups — in a modular Streamlit pipeline with a pipeline audit trail, session persistence and 20 authored development rules.

Design learnings

  • The audit trail is the feature; the charts are the decoration.
  • Split the pipeline so any single step can be re-run alone after a data refresh.
  • Choose models on documented criteria, in front of a reviewer, not on fashion.
  • Author the development rules: rules learned from the data cannot be defended to an underwriter.

Control it provides

  • Pipeline audit + persisted sessions make results re-derivable.
  • Assumptions are recorded per step, so a change of basis is visible, not buried.
  • Output is labelled a draft for a qualified professional, never a decision.

Standard Inquirer

L4 · governancedemonstrated Python2026-05MIT

Compliance is where the governance vocabulary actually lives. Retrieval keeps every citation pinned to the standard's text instead of a model's recollection of it.

What it is

Conversational compliance self-assessment against 40+ APRA prudential standards — CPS, LPS, LRS, CPG, LPG and Actuarial Standards — retrieved from a local vector knowledge base, with adaptive questioning, three-phase answer extraction and a severity-ranked gap report.

Design learnings

  • Retrieval beats memory: a citation must come from the document, not the weights.
  • Ask adaptively — a static form buries the answer in irrelevant questions.
  • Severity ranking is what turns a gap list into a work plan.
  • Version the knowledge base, or last quarter's assessment can't be reproduced.

Control it provides

  • Cites the exact standard each finding is assessed against.
  • Records which questions were asked, not just the answers given.
  • States plainly that self-assessment is not independent assurance.

LLM_Status_Watch

L5 · operationsin service Python2026-10MIT

A 21.9-hour exam on one shared local server turns capacity into a scheduling problem. This daemon is a small reason the benchmark could be run at all — the observation tool is part of the measurement system.

What it is

A Raspberry Pi daemon that reads the local LLM server's Prometheus metrics and pushes your phone when it goes idle or stops answering. Nothing installed on the GPU host; standard library only (no pip, no jq), 45 offline state-machine checks, a loopback-only viewer, and the notification secret is the topic name.

Design learnings

  • Stdlib-only is a deployment feature: fewer moving parts on the one box that must not fail.
  • State machines need explicit “dead” and “offline” states, not just a poll loop.
  • A local model is a shared server with a queue — operate it like infrastructure.

Control it provides

  • Availability monitoring, which is a model-risk control and not just ops hygiene.
  • No credentials and no software on the GPU host — nothing extra to compromise.
  • Fully self-hosted notifications: no third-party SaaS inside the loop.

Data Schema Analyser

L3 · plumbingdemonstrated Python2026-04MIT

Every study above begins by joining tables nobody documented. This is two years of awkward joins compressed into a tool — unglamorous, and the foundation everything later stood on.

What it is

Upload data dictionaries, describe what you want in plain language, and get join strategies, Graphviz ERDs and executable pandas — with EAV detection and pivoting handled automatically, and sessions you can save and hand over.

Design learnings

  • Search by concept, not column name — the column you need is never called what you expect.
  • Many-to-many needs explicit dedup guidance or the join silently duplicates your exposure.
  • Generated code must be reviewed before it runs; execution is a separate, deliberate step.

Control it provides

  • Schema knowledge becomes artefacts (ERD + join rationale) that outlive the analyst.
  • Reviewable generated code instead of invisible magic.

Excel-AI-Automator

L3 · plumbingdemonstrated Python2026-05—

Most of the industry still lives in Excel. Automation only lands there if a human can see and edit every step before it touches a workbook.

What it is

Natural language to a reviewable list of 19 Excel operations, executed step by step with visible status — plus a rule-based offline mode that works with no model at all, and a manual builder fallback.

Design learnings

  • Always ship an offline path; the deterministic fallback is the honest one.
  • Propose-then-execute beats autonomous execution in any tool that can destroy work.

Control it provides

  • Editable step list = a real human-in-the-loop checkpoint.
  • No hidden writes; every action is named before it runs.
  • Functions with zero LLM availability, so no one is locked out.

Piticle_Life

L6 · craftpre-registered Python2026-10—

It keeps the pre-registration habit sharp: the same discipline that makes the actuarial studies credible, practised on a hobby where there is no excuse for sloppiness.

What it is

A particle-life society of behavioural person-types running headless on a Raspberry Pi 2 and watched through a loopback-only stdlib viewer. Questions were written in SPEC.md before the sweeps; 48 runs, 139 tests, and no LLM at runtime, ever.

Design learnings

  • Write the question before the sweep — afterwards, any pattern will look like one.
  • Publish the noise floor: 2 of 3 claims failed it, and that is the interesting result.

Control it provides

  • Pre-registration + noise floor + tests: the benchmark template at hobby scale.
  • Deterministic simulation, so any claim can be replayed by a critic.

Pixel_Storybook

L6 · craftdemonstrated Python2026-10—

My sandbox for the observe → critique → revise loop that the benchmark's tool use needs. Failures here are cheap, visible and instructive in a way insurance results never are.

What it is

A local vision-language model paints pixel art by writing code that places pixels, looking at the render, naming what is wrong by coordinate and rewriting the code. No diffusion. Per-pass scripts, plates and critique JSON are kept, every model call is logged, and 44 tests run offline.

Design learnings

  • Critique must be grounded — coordinates, not adjectives — or the loop cannot converge.
  • Log every model call or the loop is undebuggable.
  • Vision-through-code beats pixel diffusion when you need the output explainable.

Control it provides

  • Artefacts per pass: the reasoning trail is inspectable, not just the picture.
  • A deterministic harness around a stochastic core — the same shape as the underwriter.

little_games

L6 · craftself-contained HTML2026-10—

The generator discipline at its purest: build the guarantee into the generator, and never let difficulty be a label you paste on afterwards.

What it is

Two dependency-free browser games. The hard one generates pattern-reasoning boards from hidden rule sets where every wrong tile breaks exactly one rule — seeded, replayable, and playable offline.

Design learnings

  • Guarantee uniqueness by construction instead of checking for it afterwards.
  • Difficulty is a generator parameter, not a post-hoc rating.

Control it provides

  • A seeded board is a test item you can hand someone else and expect them to see.
  • Zero dependencies: it will still run, and still be checkable, in five years.
